# LotSizingDataModel 1.2.0 Stable Release Checklist

Alpha.44 prepares the project for stable promotion but does not itself create a
tag or release.

Before promoting `1.2.0-alpha.44` to `1.2.0`:

- [ ] alpha.44 validated candidate is the exact local baseline;
- [ ] repository is clean;
- [ ] `PUBLIC-API-CONTRACT.json` is unchanged or explicitly reviewed;
- [ ] `XML-COMPATIBILITY-CONTRACT.json` is unchanged or explicitly reviewed;
- [ ] public API consumer smoke is GREEN;
- [ ] XML compatibility smoke is GREEN;
- [ ] scientific governance is GREEN;
- [ ] warnings-as-errors closure is GREEN;
- [ ] build outputs are purged before canonical validation;
- [ ] `Build-Validated.ps1` is GREEN;
- [ ] README/release documentation matches the stable version;
- [ ] `CITATION.cff` version is promoted from prerelease to `1.2.0`;
- [ ] no UI dependency exists in foundational assemblies;
- [ ] no dependency toward MLLPAlgorithm exists;
- [ ] release assets and SHA-256 manifests are generated by the canonical
      release pipeline;
- [ ] push, tag and GitHub Release occur only after explicit authorization.

The stable promotion should be a dedicated candidate whose purpose is version
and release identity, not new scientific functionality.
